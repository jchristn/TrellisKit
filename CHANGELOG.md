# Changelog

All notable changes to TrellisKit are documented in this file.

## [Unreleased]

### Added (check-in links open the app)

- Check-in QR links (`https://{domains.web}/app/check-in?...`) open the app's check-in screen. iOS: `associatedDomains` gains `applinks:{domains.web}` next to `webcredentials:` (when `mobile.appleTeamId` is set), and `/.well-known/apple-app-site-association` gains an `applinks` section limited to `/app/check-in` (legacy `paths` and `components`), so no other website page opens the app; password autofill is unchanged. Android: a verified (`autoVerify`) `VIEW` intent filter for `https` on `domains.web` with path `/app/check-in` only (when `mobile.androidCertFingerprints` is set), and `/.well-known/assetlinks.json` adds `delegate_permission/common.handle_all_urls` beside `get_login_creds`. Incoming https links are mapped through `resolveAppLink` in `mobile/app/+native-intent.js`. Native configuration change: requires a new store build.

- Curricula grouped by rank: Lesson items complete from library progress, Series items when every published lesson is complete, CatalogEntry (identifiers stored as text) and Custom items by self-completion or verification.
- Attendance check-in for events and venue schedule sessions (`{venueId}:{sessionIndex}` on a date, window measured in the venue's time zone) with rotating codes and QR payloads (`attendance.checkInWindowBeforeMinutes`, `attendance.checkInWindowAfterMinutes`, `attendance.codeRotationSeconds`), staff check-in, the roster, and the member's own attendance.

Notifications `RankPromoted` (with the `rank_promoted` email) and `LineageVerificationRequested`; audit actions for every award, revoke, verification, and check-in; account export sections and account deletion.

### Added (saves and private collections)

- Generic saves: members save lessons, series, catalog entries, venues, instructors, events, feed posts, and forum threads (`PUT`/`DELETE /api/v1/me/saves/{targetType}/{targetId}`, idempotent), list them with target summaries (`GET /api/v1/me/saves`, `POST .../enumerate`, filters `targetTypes`, `collectionId`, labels, tags, note search), and ask the saved state of up to 100 targets at once (`POST /api/v1/me/saves/state`). A saved target the member can no longer open is listed as unavailable with no title, image, or link.
- Named private collections (`/api/v1/me/save-collections`: list, create, rename, order, delete; deleting a collection keeps its saves). Collection memberships only ever link a save and a collection of the same member and property; the database refuses any other link.
- Schema 126 adds the property-scoped tables `favorites`, `favoritecollections`, and `favoritecollectionitems` (purged before `users`); labels and tags use the shared metadata tables (target types `Favorite`, `FavoriteCollection`). Save notes (at most 500 characters, visible to the member and moderators) pass the word filter and write `contentchanges` rows (new content changelog source installed by migration 126).
- Target summaries resolve through the content target registry (`ContentTargetProvider.SaveSummaryAsync`, overridable for images); `CatalogEntry` resolves as unavailable until a catalog provider registers. Posts and threads follow the feed and forum visibility rules; `FavoriteService.RegisterResolver` lets a module replace a type's resolver. Deleting or purging a lesson, series, venue, instructor, event, post, or thread deletes every save of it.
- `features.saves` (default true), the `saves` kill switch, and the `saves` access feature key (gating saves writes in `PartiallyGated`). Settings `saves.maxPerMember` (default 2000, 100 to 20000) and `saves.maxCollectionsPerMember` (default 50, 1 to 500), `409 LimitReached` beyond them. Metrics `trelliskit.saves.created` and `trelliskit.saves.removed` by target type. Account exports add `saves` and `saveCollections`; account deletion deletes both.
- Shared client: `shared/src/favoritesApi.js` (`saveItem`, `unsaveItem`, `listSaves`, `saveState`, `listSaveCollections`, `createSaveCollection`, `updateSaveCollection`, `orderSaveCollections`, `deleteSaveCollection`) and `shared/src/favorites.js` (`FavoriteTargetType`, `createSaveStateBatcher`). Documented in `REST_API.md` ("Saves"), `docs/TRELLISKIT.md` section 17, `docs/ENUMERATION_AND_METADATA.md` section 2.6, and the Postman folder "Saves"; covered by the `Saves` backend suite.

### Added (discount codes)

- Sign-up codes and batches can be discount codes (`grantType: "Discount"`): percent off (1 to 100) or an amount off in USD, for the first year (`discountDuration: "Once"`) or every renewal (`"Forever"`), on web (Stripe) checkout only. Migration 95 adds the discount columns and `stripecouponid`, and lets a redemption have no entitlement
- `POST /membership/stripe/checkout` accepts `{ code }`: the server validates the discount code (same `400 InvalidCode` for every reason, rate limited like validation), creates the code's Stripe coupon on its first checkout (`IStripeClient.CreateCouponAsync`, reused after that; a changed discount gets a new coupon), applies it with `discounts[0][coupon]` (omitting `allow_promotion_codes`), and stores `signupCodeId` in the session and subscription metadata
