# Catalog public pages

Published exercise and technique entries have server-rendered public pages at `/catalog/{slug}`. The `publicPages.catalogPath` setting changes the first segment; it defaults to `catalog` and must be distinct from the other public page paths and the reserved website routes. Both `publicPages.enabled` and `features.catalog` must be on. `features.catalog` defaults to off, so a property without it has no catalog pages, sitemap entries, or catalog routes (404 `NotAvailable`).

The public-page resolver handles `/api/v1/public/pages/resolve/{path}/{slug}` through the website proxy. It reads the property-scoped exercise catalog, never a parallel SEO store. Draft, InReview, Rejected, Archived, moderated, deleted, and missing entries all return the same noindex HTML 404 by slug or identifier. A Published identifier or differently cased slug redirects to the current canonical slug. Catalog edits return an entry to review; previous slugs are not reserved redirects.

Pages include canonical URLs, Open Graph and Twitter metadata, visible breadcrumbs, ordered instructions, curated details, and source links with their stored license and attribution. Output is escaped. Only Published, unmoderated, undeleted relationship targets appear, using one enumeration capped at 50 relationships. Private review notes, author and reviewer identifiers, generator identifiers, staff metadata, and unverified lesson references are not rendered.

The structured data describes the reviewed instructional content as [CreativeWork](https://schema.org/CreativeWork) and its navigation as [BreadcrumbList](https://schema.org/BreadcrumbList). A catalog entry is not automatically a prescribed routine, so it does not assert [ExercisePlan](https://schema.org/ExercisePlan), clinical benefits, ratings, or reviews. Schema dates use the stored publication and update timestamps, and citations use the same visible public source references.

The sitemap index includes `sitemap-catalog-{n}.xml` only when Published entries exist. Its file name stays stable when the configured page path changes. Property-scoped queries filter Published, unmoderated, and undeleted rows, order by identifier, and obey the service's 10,000-URL and 100-file bounds per kind. Each URL uses the current slug and `updatedUtc` as `lastmod`. Unpublishing or deleting an entry removes it from subsequent sitemap responses. Catalog pages and catalog child sitemaps require cache revalidation on every request, so withdrawal takes effect promptly. The website proxy (`docker/www/nginx.conf`) forwards `/sitemap-catalog-{n}.xml` to the backend.

Validation is in `CatalogPublicPageSuite` (resolver and sitemap requests covering Published versus every review state, identifier redirects, safe text and source attribution, private relationship omission and target withdrawal, canonical metadata and valid JSON-LD, the configured path, the `features.catalog` gate, bounded pagination, timestamp updates, withdrawal, and soft deletion) and in `CatalogModalitySuite` and `CatalogApparatusSuite` (escaped descriptor and apparatus text). Tests use local catalog fixtures and the neutral sample property.
